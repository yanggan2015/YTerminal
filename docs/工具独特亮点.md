# 主流终端 / 串口工具的「独特亮点」清单与集成矩阵

> 本文回答一个问题：**每个工具为什么有人用？** 不是功能对照表，而是「别人非它不可的理由」。
> 每条亮点都对应到 YTerminal 的落点（文件 / 命令 / 状态），并标注实现状态：
> ✅ 已实现　◐ 部分实现　○ 未实现（含原因与计划）
>
> 关联文档：`docs/功能清单.md`（54 条功能对照）、`docs/评分表.md`（多维打分）、`docs/执行记录.md`（可交接过程）。

---

## 1. 逐工具拆解

### 1.1 WindTerm（免费 + C 语言性能，最像本项目的对标对象）

| # | 为什么有人用它（独特理由） | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **C 实现、内存占用极低**：老机器 / 多开 20 个标签也不卡 | 纯 C + 自绘 VT，无 Electron；单 exe 275 KB | ✅ |
| 2 | **内置文件管理器，且跟随终端当前目录** | 双栏 SFTP；远端 cwd 独立维护（跟随 cwd 待做） | ◐ |
| 3 | **命令自动补全 / 历史提示**（输入即提示历史命令） | 命令面板有模糊搜索，但终端输入行无补全 | ○ |
| 4 | **Zmodem 拖拽即传**（串口 / SSH 都能用） | 未实现 | ○ |
| 5 | **绿色便携**：拷走目录即带走全部配置 | `portable.flag` + 数据目录重定向 | ✅ |
| 6 | **同步输入 / 多标签分屏** | 广播输入 + 左右/上下分屏 + 比例记忆 | ✅ |

**结论**：WindTerm 的核心是「轻 + 全 + 免费」。我们的体积与启动速度已对齐，差在**输入行补全**和**Zmodem**。

---

### 1.2 SecureCRT（企业合规、脚本自动化、VT 仿真精度）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **合规级 SSH 算法套件**（FIPS、各类 KEX/ cipher 可关可开） | 依赖系统 OpenSSH，算法由 ssh.exe 决定 | ◐ |
| 2 | **脚本引擎**（VBScript/Python）做批量登录、巡检 | 端口转发管理器 + 命令面板，但无脚本执行入口 | ○ |
| 3 | **端口转发三件套**（本地 / 远程 / 动态 SOCKS） | `L:/R:/D:` 逐行校验 + 规范化写回 | ✅ |
| 4 | **会话树 + 多协议导入**（SecureCRT / PuTTY / ssh config） | `importer.c` 支持三类导入 | ✅ |
| 5 | **精确 VT100/220 仿真**（老设备、 curses 程序不乱） | 自研 `vt.c` 46 KB，46 条单测 | ✅ |
| 6 | **打印 / 会话日志 / 审计** | 日志开关 + 时间戳文件 | ◐ |

**结论**：SecureCRT 卖的是「企业敢用」。我们补上了转发与会话导入，缺**脚本钩子**与**审计级日志策略**。

---

### 1.3 MobaXterm（一体化瑞士军刀，Windows 运维事实首选）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **内置 X Server**：SSH 里直接跑 GUI 程序 | 不做（体积与依赖代价高，明确不跟） | ○ |
| 2 | **SFTP 双栏 + 队列 + 拖拽**：左边本地右边远端 | **本轮重做**：双列表、多选、队列、后台线程、横向滚动 | ✅ |
| 3 | **MultiExec**：一条命令发到多台机器 | 广播输入（同窗口多标签） | ◐ |
| 4 | **会话即配置 + 便携版** | 会话 JSON + 便携模式 | ✅ |
| 5 | **网络工具箱**（ping/telnet/ssh 一键） | 快速连接 + 命令面板 | ◐ |
| 6 | **隧道管理图形化** | 端口转发管理器（逐行校验） | ✅ |

**结论**：MobaXterm 的护城河是 X Server 与「一站式」。X Server 不做，但**双栏 SFTP + 队列**这块本轮补齐，已经不输它的文件页。

### 1.4 Xshell（中文体验 + 组合会话 + 快捷命令）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **中文界面与中文文档最完整** | 全中文 UI、中文文档 | ✅ |
| 2 | **快速命令栏**（底部一排可点按钮，常发命令） | 命令面板（键盘流），无底部常驻按钮条 | ◐ |
| 3 | **组合会话 / 多窗口平铺** | 标签 + 分屏 | ◐ |
| 4 | **发送键序列**（一键发一串按键） | 快捷键 + Alt 字母发 ESC 序列 | ◐ |
| 5 | **Zmodem / 日志 / 代理** | 日志 ✅；Zmodem、代理未做 | ◐ |

**结论**：Xshell 的差异点是「面向不会命令行的中文用户」。我们的命令面板是键盘优先，**下一步应加底部快速命令条**。

---

### 1.5 PuTTY（极简、事实标准、工具链）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **单文件、零依赖、永不崩溃** | 单 exe + 静态链接 | ✅ |
| 2 | **plink / pscp 命令行工具链**（可被脚本调用） | 无 CLI 模式 | ○ |
| 3 | **串口连接最稳**（COM 口 + 流控） | `NEW_SERIAL` + 波特率/数据位/校验/流控 | ✅ |
| 4 | **被无数教程引用**（默认选择） | 导入 PuTTY 会话 | ✅ |

**结论**：PuTTY 赢在「最小可信」。我们缺的是 **CLI companion**（`ytcli -e "cmd"`），这是脚本化运维的入口。

### 1.6 Tera Term（串口 / 嵌入式调试 + 宏语言）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **TTL 宏语言**：自动登录、批量烧写、日志归档 | 无宏引擎 | ○ |
| 2 | **ZMODEM / XMODEM / Kermit 文件传输** | 未实现 | ○ |
| 3 | **串口日志 + 时间戳 + 十六进制显示** | 日志 ✅；HEX 视图未做 | ◐ |
| 4 | **UTF-8 / 多编码切换** | 编码切换已支持 | ✅ |

**结论**：Tera Term 是嵌入式工程师的默认选择。**Zmodem 与 HEX 视图**是我们要补的两块。

### 1.7 Tabby（现代 UI + 插件化）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **好看的现代界面 + 主题** | 自绘主题、亮/暗色 | ✅ |
| 2 | **插件体系**（社区扩展） | 无插件机制 | ○ |
| 3 | **SSH + 串口 + 本地 三合一** | 三种协议均支持 | ✅ |
| 4 | **快捷命令 / 分屏** | 命令面板 + 分屏 | ✅ |

**结论**：Tabby 赢在「颜值 + 可扩展」。颜值我们跟上了，**插件化**不做（纯 C 单体更稳）。

### 1.8 Windows Terminal（GPU 渲染 + 命令面板 + JSON 配置）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **GPU 加速渲染、Unicode/Emoji 完整** | GDI 自绘 + 宽字符处理，非 GPU | ◐ |
| 2 | **命令面板 `Ctrl+Shift+P`** | **已实现** 26 命令 + 会话模糊搜索 | ✅ |
| 3 | **Pane 分屏 + 快捷键** | 左右/上下 + 比例持久化 | ✅ |
| 4 | **JSON 配置 + 可读文档** | `settings.json` / `sessions.json` | ✅ |
| 5 | **WSL / 多 Shell 集成** | 本地 Shell 可指定 exe | ◐ |

**结论**：Windows Terminal 的现代交互（命令面板、分屏、JSON）我们已对齐；差在 GPU 渲染（代价高，暂不做）。

### 1.9 iTerm2（macOS 生产力标杆）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **热键下拉窗口**（全局快捷键呼出） | 无全局热键 | ○ |
| 2 | **Shell 集成**（标记命令边界、跳转上个命令） | 无 shell 集成脚本 | ○ |
| 3 | **触发器 Triggers**（匹配文本自动动作） | 关键字高亮是静态版；无动作触发 | ◐ |
| 4 | **tmux 集成 / 粘贴历史** | 无 | ○ |

**结论**：iTerm2 的杀手锏是「终端里做 IDE 级导航」。**触发动作**（高亮 → 自动回复/告警）是我们高亮的自然下一步。

### 1.10 Termius（跨平台同步 + 团队协作）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **云同步会话**（多设备一致） | 本地 JSON；可放网盘目录 | ◐ |
| 2 | **团队共享主机清单** | 无 | ○ |
| 3 | **Snippets（命令片段）** | 命令面板可搜命令，无自定义片段 | ◐ |

**结论**：Termius 卖「同步 + 协作」。我们保持**本地优先**（不联网更安全），同步交给用户自己的网盘。

### 1.11 FinalShell（国产运维：服务器监控面板）

| # | 为什么有人用它 | YTerminal 落点 | 状态 |
|---|---|---|---|
| 1 | **CPU/内存/网络实时曲线**（SSH 里直接看） | 无监控面板 | ○ |
| 2 | **SFTP 与终端联动**（跟随 cwd） | 双栏 SFTP，cwd 未联动 | ◐ |
| 3 | **一键部署 / 命令历史** | 无 | ○ |

**结论**：FinalShell 赢在「运维看板」。可作为**侧栏插件式面板**（读 `/proc`）后续加，不影响主流程。

## 3. 本轮真正集成的东西（可验证）

1. **SFTP 双栏管理器**（MobaXterm / WindTerm 的核心卖点）
   - 左本地 / 右远端，两个独立路径栏，双击目录进入，`..` 回上级；
   - 多选 + 上传/下载入队，`scp` 后台线程顺序执行，进度条 + 「正在传输 i/n」；
   - 远端目录读取改为**后台线程**，网络慢不再冻结界面；
   - 本地列表 `WS_HSCROLL` + 横向滚动，长文件名可读；
   - 失败提示带退出码，传输中禁止关闭窗口。
2. **分屏比例持久化**（Windows Terminal / iTerm2 习惯）
   - `settings.json` 新增 `split_v_pct` / `split_h_pct`，拖拽松手即写盘，重开沿用，越界回落 50%。
3. **工程级修复：UNICODE 构建宏**
   - 发现 `ListBox_AddString` 实际走 ANSI 版本，导致列表只显示首字符；`build.ps1` 增加 `-DUNICODE -D_UNICODE`，全工程字符串路径统一。
4. **界面冒烟测试**（把「看起来对」变成「断言对」）
   - `scripts/ui-smoke.ps1`：启动真实 exe，逐个打开命令面板/快捷键/端口转发/设置/SFTP，断言窗口类名、控件存在、本地列表条数与首项，退出码可用于 CI。

## 4. 仍未集成的「独特亮点」（诚实清单）

| 缺口 | 来自 | 难度 | 计划 |
|---|---|---|---|
| 命令历史 + 输入行补全 | WindTerm / Xshell | 中 | 记录本地输入行 → ↑ 召回 → 下拉候选 |
| Zmodem 收发 | WindTerm / Tera Term / Xshell | 高 | 状态机 + 拖拽触发 + 进度 |
| 脚本 / 宏引擎 | SecureCRT / Tera Term | 高 | 先做「启动时执行命令列表」，再评估表达式 |
| 快捷键自定义 + 冲突检测 | Xshell / SecureCRT | 中 | 设置里键位表 + 保存时冲突提示 |
| 快速命令条 | Xshell | 低 | 底部一排可点按钮，配置存 sessions.json |
| 服务器监控侧栏 | FinalShell | 中 | 解析 `/proc/stat`、`/proc/meminfo` 画迷你曲线 |
| CLI companion | PuTTY plink | 中 | `YTerminal.exe --exec "cmd"` 无窗口执行 |
| 触发动作 | iTerm2 Triggers | 中 | 高亮规则加 `=> run:xxx` 动作 |

> 结论：**双栏 SFTP 这块已对齐 MobaXterm**；剩余差距集中在「输入效率（历史/补全/快捷键自定义）」与「文件传输（Zmodem）」两条线，按上表顺序推进。
