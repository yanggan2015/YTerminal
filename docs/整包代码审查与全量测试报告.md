# YTerminal 整包代码审查与全量测试报告

- 报告日期：2026-11-16
- 测试对象：`C:\code\YTerminal`（全仓库，非仅 GUI 目录）
- 测试版本：按当前源码重新编译的 `YTerminal.exe`（849,056 字节）
- 测试环境：Windows 11 10.0.26100，MSYS2 / MinGW-w64 GCC 16.2.0，1280×720 逻辑分辨率
- 测试约束：**未修改任何源码**；全部运行测试在仓库外的隔离副本中进行

## 1. 结论摘要

本次把审查范围从 `src/ui` 扩展到整包：清点 12 个顶层目录、约 250 KB C 源码，完成静态审查、编译告警检查和 28 项运行测试。结论如下。

**严重问题（P0，3 项）**

1. **删除任一会话书签必定导致进程崩溃**。实测退出码 `0xC000041D`，耗时约 1.07 s，`sessions.json` 未写入。根因是 `app_tree.c` 在栈上分配 `YtSession keep[512]`，合计 2,285,568 字节，超过 MinGW 默认 2 MB 线程栈。用同一份源码加 `-Wl,--stack,8388608` 重编后，同一操作正常完成（书签 7→6）。
2. **桥接服务默认无鉴权，且允许任意跨站请求**。`GET /state`、`POST /action` 不带令牌均返回 200；响应头 `Access-Control-Allow-Origin: *`；实测通过 `POST /action {"id":"btn.close"}` 成功远程点击控件。本机任意网页均可驱动该应用。
3. **源码内置真实服务器凭据**。`profile_store.c` 默认书签硬编码 `root` / `!!!zzxxccvvbbnnmmMMNN12345678` 与 `Ncti2023`，并会自动写入用户的 `sessions.json`。这是凭据泄露，不只是示例数据问题。

**高危问题（P1，10 项）**：脚本在 UI 线程逐行 `Sleep(80)`，30 行脚本实测冻结界面 2.76 s；导入会话不做校验、不备份，畸形文件可覆盖配置（实测畸形文件启动后被静默重写为 7 条默认书签）；多实例共用配置且第二个实例桥接端口冲突、完全没有桥接；SSH/Telnet 关闭路径存在释放后使用；ZMODEM 文件名拼接 shell 命令；凭据库长度与除零边界缺失等。

**对上一版 GUI 报告的纠正**。上一版测试的二进制由旧源集构建，本轮改用当前源码重编后，以下 4 条判断不成立，已撤销：首标签空白、`cmb.kind` 只有 5 项、重连完全无动作、本地连接按钮不读取 Shell 下拉。当前实测：首标签有提示符且可输入；类型下拉 4 项（Local/SSH/Serial/Telnet）；重连本地会话会写状态栏“本地会话无需重连，请新建”；Shell 下拉参与本地启动命令。

**总体评价**：主体交互可用，启动约 0.5 s，常规动作往返开销低于 2 ms；但稳定性、配置安全和多实例能力不达可交付标准。建议先修 3 项 P0，再处理 P1 中的生命周期与导入问题，最后处理交互一致性缺陷。

### 2.1 构建一致性

仓库存在两套互不一致的源文件清单：

| 构建入口 | 源集 | 产物能力 |
|---|---|---|
| `Makefile` | `main.c`、`term_view.c`、`pty_session.c`、`serial_session.c`、`session.c`、`dlg.c` | 仅 Local/SSH/Serial，无 Telnet/SFTP/转发/ZMODEM，不链接 libssh2 |
| `build.ps1` | `src/ui` 6 文件 + `src/core` 6 文件 + `src/engine` 9 文件 + bridge | 当前完整功能 |

用旧 `Makefile` 源集可成功编译出 `legacy.exe`（exit=0）并独立运行，说明两条构建路径会产出两个不同产品。旧 `src/main.c` 的连接类型仍只有 `0 local / 1 ssh / 2 serial`。这是可复现性与维护性缺陷：任何人按 README 或 Makefile 构建，得到的都不是被测产品。

### 2.2 编译告警

编译参数：`-O2 -Wall -Wextra -Wformat=2 -Wshadow -Wstrict-prototypes`，退出码 0，共 **24 条 warning**（明细落盘 `wbuild\warnings.txt`，130 行）。按类型归纳：

| 类型 | 代表位置 | 风险判断 |
|---|---|---|
| `strncpy` 可能截断（511/255 字节） | `app_connect.c:23`、`app_tree.c:59`、`main.c:503/541`、`profile_store.c:133`、`forward.c:103/121`、`local_pty.c:235`、`ssh_session.c:42/53`、`zmodem.c:52` | 目标串可能缺少结尾 0，后续按 C 字符串使用会越界读 |
| `snprintf` / `%s` 截断 | `main.c:540/1161`、`ssh_session.c:42/53`、`local_pty.c:235` | 路径或命令被截断后指向错误对象 |
| 变量遮蔽 `-Wshadow` | `main.c:294/308` | 易误用外层 `i`，当前逻辑未触发错误 |
| 结构体初始化缺字段 | `main.c:230`（`WINDOWPLACEMENT`）、`main.c:266`（`MONITORINFO`） | 依赖零初始化，当前可接受但不稳健 |
| `FARPROC` 强转 | `local_pty.c:183-185` | 函数签名不一致，属未定义行为 |
| 无符号转 `WORD` 溢出 | `win_ui_bridge.c:425`（4294967195→65435） | ListView 状态掩码计算错误，桥接选择列表项失效 |
| 头文件顺序 / pragma | `winsock2.h`、`win_ui_bridge.c:27` | 构建告警噪声 |

告警本身未导致运行失败，但截断类告警与静态审查发现的“缺结尾 0”“路径拼接越界”相互印证，应作为缺陷修复的一部分处理。

## 6. 修复优先级建议

**第一批（阻断发布）**

1. `yt_app_tree_delete_index` 去掉 2 MB 级栈数组，改堆分配；同时给 `build.ps1` 增加显式栈大小，避免其他深调用路径复发。
2. 桥接默认生成并强制校验令牌，绑定 `127.0.0.1`，移除 `Access-Control-Allow-Origin: *`，对 `/state`、`/ui-tree`、`/action` 全部鉴权。
3. 删除 `profile_store.c` 中真实凭据；对已有用户配置提供迁移提示，避免继续扩散。

**第二批（数据与生命周期）**

4. 导入会话：解析校验 → 备份 → 原子替换；解析失败保留原文件并报错；加载器遇到非法配置不得静默覆盖。
5. 脚本执行移出 UI 线程；逐行延时改为定时器，保持界面可响应。
6. SSH/Telnet/转发统一“停止线程 → 确认退出 → 释放”顺序；关闭标签与完成消息用会话代次校验。
7. ZMODEM 改用 argv 或严格转义；`cred_store` 增加长度与空文件校验。
8. 多实例：单实例激活并把已有窗口置前，或每实例独立端口与配置目录。

**第三批（功能与一致性）**

9. 关闭分屏隐藏/销毁 peer 终端；主题与标签着色要么实现真实效果，要么从菜单移除。
10. 串口类型切换清空无效端口；属性对话框增加端口/波特率校验与默认焦点。
11. 修正快捷键文案与实现；F11/F3 在终端焦点下同样生效。
12. 处理 24 条编译告警中的截断与函数强转，尤其是 `strncpy` 缺结尾 0 的路径。
